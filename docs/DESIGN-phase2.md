# Retake — phase 2 contracts: components, themes, editor, review

Types: `packages/components/src/types.ts` (component contract), `packages/editor/src/plan-types.ts` (EditPlan),
`packages/core/src/types.ts` (scenario, timeline, template — and `ComponentKind`, `COMPONENT_KINDS`, `ComponentRef`,
which `@retake/components` re-exports: core is their single source of truth). Reference look: `docs/reference/look.md`.
Product rules: docs/SPEC.md §0, §9–§12.

## 1. Components (`packages/components`)

Every visual element is a component (SPEC §11). Nothing visual is hard-coded in the editor.

### 1.1 Layout of a component
```
<namespace>/<name>/
  component.yaml      # ComponentManifest (id, version, kind, name, description, slots, params JSON Schema,
                      # tokens, duration, geometry for layouts, preview samples, publisher/license/tags)
  index.tsx           # default export: React.FC<ComponentProps<P>> (Remotion; useCurrentFrame is segment-relative)
  preview.png         # generated by `retake components preview` (960×540) — never hand-edited
  preview.json        # its sidecar: component, version, theme, moment, sample screen, source files + hash
  README.md           # the author's notes + a generated block (name, id, kind, the preview, slots, params)
```
Rules for implementations: read every colour/font/logo from `props.theme`; size everything with `props.unit`;
deterministic (no Math.random/Date); no network; may import only `react`, `remotion` and
`@retake/components/kit` (shared helpers: fades/rises/stagger, easing presets, fitText, Logo, Wordmark,
background renderer, safe-area helpers; L3.7: also the renderer primitives `useCurrentFrame`, `useVideoConfig`, `Img`,
`AbsoluteFill`, `Sequence`, `random`, re-exported from remotion in `kit/renderer.ts`, which the scaffolds import instead
of `remotion`). Text slots must never overflow: fitText shrinks within bounds.

L2.7 rules for frames around a capture:
- **Geometry from the capture aspect.** Every layout writes its geometry as expressions: browser and laptop keep the
  capture's aspect exactly (a width param, the height following, capped so the caption block fits); the phone and the
  tablet clamp it to device proportions (phone 0.42–0.62, tablet 0.62–1.6; the tablet switches between portrait —
  caption beside — and landscape — caption below — with a 0/1 `land` var computed from `aspect`, since expressions have
  no comparisons). A capture outside the device range is letterboxed / pillarboxed: `planLayout` keeps the declared
  screen rect as `PlanLayout.display` (`LayoutRects.display`) when the fitted capture does not fill it, and the layout
  paints it with the theme background (raw included).
- **Device drawing** is CSS/SVG only, every tone from the theme (kit `deviceTones(theme, finish)`: glass = the night
  tone, metals mixed from the theme's dark and light tones); the classic window-control colours are the one exception,
  exported as neutral system colours (`SYSTEM_COLORS`, `controls: theme` tints them). The phone draws a status bar
  (time, signal, battery) around the Dynamic Island ABOVE the capture, so the island never hides the page.
- **Captions over the capture.** Caption and overlay components now receive the clip layout's `rects`. caption-overlay
  (`position: over`, default) draws a band over the bottom of `rects.screen` (40 px in, ≤ `max_width`), falling back
  to the caption area when the capture is narrower than 900 px (phones); the box is the kit's `captionBandBox`, which
  the review uses too (`caption-not-visible` samples it, `caption-too-long` fits in its width, the brand-mark overlap
  check is skipped). caption-below draws a paper band behind its text when the caption area lies over the capture
  (layout-raw).
- **Overlays** stay inside the capture (`rects.screen`) when they fit there, else inside the frame's safe area
  (`placeCallout` is exported and property-tested: never off-screen, pointer toward the target's centre).

L2.8 rules for the other formats (vertical 9:16, square 1:1):
- **Geometry per format.** Layouts declare `geometry_vertical` (1080×1920) and `geometry_square` (1080×1080; manifest
  key added in L2.8, `variants: [landscape, vertical, square]`). Card and browser: as tall as the format allows, a
  capture wider than 4:5 (vertical) or ≈ 4:3 (square) is **reframed** (`a: min(aspect, 0.8)` / `min(aspect, 1.32)`:
  the screen rect's aspect differs from the capture's), a narrower one (a phone) is shown whole. Devices keep their
  proportions (the capture whole, except where the phone / tablet clamp the aspect: then reframed). Raw fills the
  frame (reframed). Caption block below (220 px tall in vertical, 160 px in square) or beside a phone / portrait
  tablet in square; brand mark at the bottom right.
- **Type for the format.** Full-frame components (intro, outro, card, interstitial) size type and spacing with the kit
  `formatMetrics(variant, unit)` (`u` = unit × 1.2 in vertical, × 1.05 in square; side margins halved); caption lines
  may wrap (`captionMaxLines`: ≥ 2 in vertical / square, ≥ 3 in a column narrower than 600 design px) — the review
  measures with the same rule.

Reference-look rules shared by the six (all values design px × unit, every colour/font/logo from the theme):
- **Text is placed by its cap band** (`capTextLayout` + `<CapText>` in the kit): look.md positions are cap centres;
  the kit measures the font (canvas: cap height, ascent, descent) and puts the line box where the caps land on the
  wanted y, whatever the font. Intro and outro build a vertical rhythm of bands (logo row, kicker caps, title caps →
  baseline, rule, tagline, url) with the measured gaps and centre the whole stack, so a missing kicker or a two-line
  title stays balanced while the full stack lands on the reference positions.
- **Wordmark**: a visual height (image height; the brand name in the display font at height × 1.3 when the theme has
  no wordmark image — R-LOOK-22): intro 33, brand mark 24, outro 71.
- **Night tone** of dark cards and veils: `colors.dark` when the theme defines it, else the darker of text / paper
  (editorial: its ink `#1f1413`; motion: its paper `#11131c`); the clock ring is the night tone mixed 25 % towards
  the paper (editorial → `#544b48`; the reference measures `#544846`).
- **Readability guard**: colours that would not read on the theme background (contrast) fall back to the dark/light
  pair of the theme.
- **style_bias** (R-TPL-04): `biasMotion(bias)` → `real` = the reference motion; `balanced` / `motion` = more rise
  (×1.5 / ×2), a small scale settle (logo row, clock, crossfade 1–2 %), a tracking settle on the intro title, the
  caption rule and the clock ring draw themselves. The card layout is static at every bias (a frame never moves on its
  own).
- **Captions at clip edges**: a caption whose cue starts at the clip start enters 0.15 s late and one that ends with
  the clip leaves 0.15 s early, so two captions never double-expose in the middle of a crossfade; inside a clip, cue
  changes are back to back (out 0.25 s, in 0.35 s with a 7 px rise) and a kicker shared by contiguous cues stays.

### 1.3 Registry (`@retake/components`, implemented in L2.2)
```ts
loadComponentRegistry(opts: { root: string /* workspace */; componentsDir?; builtinDir? | null }): Promise<ComponentRegistry>
//  scans <components_dir>/<ns>/<name>/component.yaml (retake.yaml components_dir, default <root>/components) then
//  packages/components/library/<ns>/<name>/; workspace ids override built-ins (warning notice); invalid folders are
//  kept out of list() and reported in `notices` (get/resolve throw with their positioned issues)
ComponentRegistry = {
  list(kind?): ComponentInfo[]; has(id); get(id): ComponentInfo /* ComponentError: not found + did you mean | invalid */;
  resolve(ref, kind): ResolvedComponentRef  /* {id, version, kind, params (schema defaults under the given params,
                                               validated), manifest, dir, entry, source}; kind mismatch → error */;
  resolveTheme(template): Record<ComponentKind, ResolvedComponentRef | null>  /* via core resolveThemeComponents */;
  notices: RegistryNotice[]; componentsDir; builtinDir?
}
ComponentInfo = { manifest: ComponentManifest; dir: string; entry: string /* abs */; source: 'workspace' | 'builtin' }
evalLayoutGeometry(spec, params, { aspect? }): LayoutGeometry   // geometry expressions → design px (see below)
DESIGN_SPACE / VARIANTS / GEOMETRY_KEYS   // landscape 1920×1080 `geometry`, vertical 1080×1920 `geometry_vertical`,
                                          // square 1080×1080 `geometry_square` (L2.8)
parseManifest(text, file?, { folderId? }): { manifest?, issues: ComponentIssue[] }   // strict zod schema + semantic checks
validateComponent(dir): Promise<ComponentIssue[]>   // manifest, id = folder, entry exists, params schema + defaults,
//  preview samples fill required slots, layout geometry, esbuild compile (imports: react, remotion, the kit and own
//  files only; misspelt named imports; Math.random/Date/fetch/timers) — every issue {file, line, col, path, message}
createComponent(root, { id, kind, description, name?, noOverride? }): Promise<CreatedComponent>   // from scaffolds/<kind>/, validated
//  L3.2 `noOverride` (MCP component_create): refuses the `studio/` namespace (BUILTIN_NAMESPACE) and any built-in id
//  instead of overriding the built-in with a warning; the CLI keeps the override
// Previews (L2.7): bookkeeping only — rendering is @retake/editor `renderComponentPreviews`
componentSourceFiles(dir) / componentSourceHash(dir)   // manifest + entry + local imports (recursive), sha256/16
previewStatus(dir, { theme? }): { state: 'fresh' | 'missing' | 'stale', reason?, meta?, hash }
previewReadmeBlock(manifest, meta) / writePreviewReadme(dir, manifest, meta)   // README block between markers

// L4.5 (the guard-rail): manifest `engines: {kit: "1" | "^1"}` (absent = 1); KIT_API_VERSION = 1, kitMajorOf(manifest).
//  A component whose kit major is not KIT_API_VERSION is a broken folder of the registry (notice, get / resolve throw
//  "needs kit API N"): its uses fall back down the planner's chain, else render as `missing`. The 41 built-in manifests
//  carry none (kit 1).
componentFit(registry, id, use: { kind, slots?, named?, params?, file?, pages? }): { ok: true } | { ok: false, why }
//  L4.5 (critique B7): whether a component takes a use as the scenario writes it — registered and loadable, usable as
//  the kind, shows every written slot, gets every required one (written, `default_from`, a planner-filled `screen`),
//  takes the use's params (schema + defaults), a layout shows as many pages as the scene films; a user file (`video` /
//  `image` / `lottie`) takes no component. The timeline offers a non-fitting option disabled with `why`, and the
//  engine refuses that `set_field`.
```
**Geometry expressions (L2.5).** A layout's geometry may follow its params: every value of `geometry` /
`geometry_vertical` (rect `x`, `y`, `w`, `h`, `radius`) is a number or an arithmetic expression over the component's
numeric/boolean params, the geometry's `vars` (named values, computed in order) and the built-in `aspect` (capture
width / height; 16:9 when unknown). Grammar: numbers, identifiers, `+ - * / %`, unary minus, parentheses, `min`,
`max`, `round`, `floor`, `ceil`, `abs` — a manifest stays data (no component code runs in Node; the planner, the
review, the validator and later the Studio UI evaluate it). Chosen over a geometry function exported by the component
(it would execute workspace — later marketplace — code in the planner and make planning async) and over one geometry
per param value (does not scale to numbers). Contract:
- `parseManifest` checks every expression (syntax with position, unknown names with did-you-mean, string params, vars
  shadowing a param, `aspect` as a var) and the geometry evaluated with the param defaults (positive sizes, inside the
  design space); the JSON Schema accepts `number | string` (`GeometryValue`).
- `planEdit` evaluates the geometry of each layout use with its resolved params and the capture aspect
  (`evalLayoutGeometry`), then fits the capture as before (`planLayout`); a use whose geometry cannot be evaluated
  falls back to the default geometry with a warning, one that leaves the frame is a warning. `geometry.radius` wins
  over a `radius` param.
- The composition passes the evaluated layout to the layout component as `props.rects` (output px: `screen` = where
  the capture goes, `frame` = the card / device outline, `caption`, `brandmark`, `chrome`, `radius`), so the component
  never re-derives the geometry; without `rects` (unit previews) a layout falls back to its default geometry
  (layout-card's `defaultRects`, tested equal to its manifest).
- studio/layout-card: `width` sizes the card, its height follows the capture aspect (≤ 878 so the caption block
  fits), the card + 12 px + 110 px caption block is centred vertically, the caption rect is the card's left part
  (width − 340) and the brand mark rect the card's right 320 px: width 1560 at 16:9 → card {180, 40, 1560 × 878},
  caption {180, 930, 1220 × 110}, brand mark {1420, 965, 320 × 40} (look.md); width 1400 → {260, 85, 1400 × 788}.

`packages/components/scaffolds/<kind>/` are valid, theme-driven components (`scaffolds/<kind>` ids; L3.7: they import
only `react` and the kit) used by `createComponent` and, as stand-ins, by the render pipeline until the library lands. Props added for kinds that need
them: `area` (caption: the layout's caption rect), `anchor` (overlay: target box in output px), `direction`
(transition: `exiting` around the outgoing segment, `entering` around the incoming one, drawn on top; `screen` = the
wrapped segment). The kit (`@retake/components/kit`) is documented in `docs/guide/themes-and-components.md`, section "Components".

### 1.4 Themes (templates) pick components
Template gains (additive, core types + `TemplateSchema` / `TemplateFileSchema`):
```yaml
brand: { name: Atelier, url: example.com }          # used by wordmark-as-text, outro url
components:                                          # defaults per kind (string id or {id, params}); null = none
  intro: studio/intro-stack
  outro: studio/outro-stack
  interstitial: studio/interstitial-clock
  card: studio/card-title
  layout: { id: studio/layout-card, params: { width: 1560, radius: 18, shadow: soft } }
  caption: studio/caption-below                      # null = no captions
  overlay: studio/overlay-callout
  transition: { id: studio/transition-crossfade, params: { duration: 0.35 } }   # null = cut
```
Component ids match `COMPONENT_ID_RE` = `/^[a-z0-9][a-z0-9-]*\/[a-z0-9][a-z0-9-]*$/` ("namespace/name"). The pure
helper `resolveThemeComponents(template): Record<ComponentKind, {id, params, source: 'theme'|'legacy'|'default'} | null>`
(core) applies, per kind: the `components` entry as written (`null` = none; legacy params are NOT merged into an
explicit entry) → the legacy field mapping → the built-in default.

| Legacy field | Value → component |
|---|---|
| `frame.style` | card → `studio/layout-card {width, radius, shadow}` (from `frame`); browser / laptop / phone / raw → `studio/layout-<style>` (no params yet: their params schemas come with L2.7, which may map `frame.width/radius/shadow` too) |
| `intro.layout` | logo-kicker-title → `studio/intro-stack`; kicker-title → `studio/intro-minimal`; logo-only → `studio/intro-minimal {logo_only: true}` |
| `outro.layout` | logo-wordmark-tagline-url → `studio/outro-stack`; logo-tagline → `studio/outro-minimal`; logo-only → `studio/outro-minimal {logo_only: true}` |
| `interstitial.style` | dark-clock → `studio/interstitial-clock`; paper / dark → `studio/interstitial-plain {tone}` |
| `captions.position` | below → `studio/caption-below`; above → `studio/caption-below {position: 'above'}`; overlay → `studio/caption-overlay`; none → null |
| `transitions.between_scenes` | crossfade → `studio/transition-crossfade {duration}`; fade-black → `studio/transition-fade-black {duration}`; cut → null |
| (none) | card → `studio/card-title`; overlay → `studio/overlay-callout` (source `default`) |

Validation of template.yaml warns when a `components` entry contradicts a legacy field written in the same file
(the entry wins, so editing the legacy field would change nothing). The starter templates (default, editorial,
motion) declare `brand` (fictional) and an explicit `components` map consistent with their legacy fields (tested).
`FRAME_STYLE_LAYOUTS` (core) maps each FrameStyle to its built-in layout id.

### 1.5 Scenario additions (additive, core types + schema)
- `intro: false | { component?, params?, duration? }`, `outro: false | { component?, params?, tagline?, url?, duration? }`
- `interstitial: { text, kicker?, duration?, style?, component?, params? }` (`style` = legacy override, ignored with
  `component`: warning)
- new scene entry `card: { component?, params?, slots?: Record<string,string>, duration? }` + optional `id` (default
  `card-<index>`); takes no capture time; needs `component` or `slots.title` (error otherwise)
- `frame:` on a project, scenario or scene accepts a FrameStyle (`card` ⇒ studio/layout-card …) or a layout component
  id (`FrameSpec`); the project default stays `card`
- step modifier `overlay: { component, slots?, params?, duration? (0 < d ≤ 30 s), target?: TargetSpec }`
- ids are unique across scenes, cards and interstitials, default ids included; every duration is > 0
- runner: cards are recorded in `timeline.scenes` (`kind: 'card'`, `card: {component?, params?, slots?, duration?}`,
  `t_start === t_end`); a step with `overlay` records `event.overlay = {component, slots, params, duration?, target?,
  bbox? | point?}`, the anchor measured at the END of the step (after any scroll): the `target` element if given, else
  the step's own target box as the action reports it, else the cursor position (a target not found → cursor + a
  warning). `camera` targets follow the same rule (tested on the SPEC example: scroll to "Awards" with a camera on
  "Awards" records the post-scroll box).
- `caption_component: <ComponentId>` (scenario, L4.5): the caption component of every clip, between a render override
  and the theme (§2.1); an edit value (core filmedChanges leaves it out; replanEdit copies it and names it among the
  changes); validated as a component id (the registry is checked at plan time and by the Studio's `set_field`).
- `Timeline.video = { title?, intro?, outro?, frame?, template?, music?, tutorial?, target_length?, caption_component? }` (`timelineVideo()` in core): the scenario's
  edit info as written (its strings templated by the runner after the setup hooks since L1.2, `templateVideo`), the
  effective default `frame` (scenario, else project) and the template the run used — the editor never re-reads
  scenario.yaml. Optional in the schema so older timelines stay valid.

### 1.6 Artefacts: mails, documents, notifications (L2.9)
- **Capture** (runner-web): `wait_for_email` (project `mailbox`, Mailpit API or the generic JSON shape; only messages
  that were not in the mailbox at run start — listed before the setup hooks — and not taken by an earlier capture; the
  oldest match), `download` (real click; the download event — on the page or on a tab the click opens — or the
  document a new tab shows, fetched with `context.request` = the session's cookies; the tab is closed), web
  notifications (the kit wraps `Notification` and `ServiceWorkerRegistration#showNotification` once per window and
  calls the context binding `__retakeNotification`; the permission is granted by the session). Files under
  `runs/<id>/artefacts/{emails,documents,notifications}/`; images are rendered AFTER the capture in a clean browser
  (`ArtefactRenderer`: email HTML at 600 px × 2, JavaScript off, offline, CSP; PDFs with pdf.js 5 in Chromium at 2×
  CSS px → A4 1587 × 2245; icons → 192 px PNG); project documents named by `document:` slots are copied and rasterised
  by the run too. `Timeline.artefacts` lists everything components need (the editor never reads artefact files);
  notifications are also events `{action: notification, step: -1}` (excluded from step provenance by the planner).
- **Slots → media**: slot types `email`, `document`, `notification` (manifest) name an artefact; `ComponentResolver`
  resolves them through the planner's artefact index into `ResolvedComponent.media` (`EmailMedia`, `DocumentMedia`,
  `NotificationMedia` with `ds-asset:artefact-…` image URLs in `plan.assets`); the composition passes it as
  `props.media`. Unknown names: a plan warning (core validation checks `email:` / `document:` against the scenario's
  `as` names and project files). A notification overlay starts at the notification's capture time when it lies in the
  clip. `OverlayUse.componentFrames`: an overlay cut by the clip end is rendered with its own length (no early exit).
- **Transitions as components**: scene / card `transition` = a kind or a component (`SceneTransition`). **Anchors**: a
  manifest may declare `anchor` (+ `anchor_vertical`, `anchor_square`) = `{vars?, x, y, w, h}`, expressions over
  numeric params, one-hot string params (`<param>_<value>`), `frame_w/h`, `screen_x/y/w/h` (the clip's capture rect)
  and `aspect` (`evalAnchor`, checked by `parseManifest`). The planner evaluates the outgoing segment's anchor — or the
  last overlay still showing in the outgoing clip's final second — into `PlanTransition.anchor` (output px), handed to
  the transition as `props.anchor` (studio/transition-tap-open zooms out of it). The kit's `notificationBox` and
  `phoneCardGeometry` mirror the anchors of the notification and phone components (tested equal).

### 1.7 Tutorial overlays & story cards (L2.10)
- **Switches, not steps**: `tutorial` on the scenario, a scene or a step (`true` / `false` / a mode / `{component?,
  params?}`; core `resolveTutorial`, most specific wins; `progress` scenario-only). The runner copies them into the
  timeline (`video.tutorial`, `scene.tutorial`, `event.tutorial`) with what the overlays need: `press` keys, `type`
  timing (`t_type`, `t_typed`, `t_enter`) and, for a `type` without `into`, the focused field as its target.
- **Planner** (`editor/src/tutorial.ts`, pure, `TUTORIAL_TIMING`): overlay uses with `tutorial`, `moment` (the frame
  of the press / click, relative to the overlay), `track` (anchor boxes over time in source CSS px; the composition
  glides between them with `trackBoxAt`), `region` (a capture region the composition renders as the component's
  `screen`: the loupe), `layer: 'screen'` (under caption, brand mark and the other overlays: the spotlight). The
  progress bar is one `plan.tutorial.progress` over the video with `chapters`. The composition hands overlays `avoid`
  (output px): the caption band of a caption drawn over the screen while a cue is on (`overlayAvoid`, `captionBandOver`)

### 1.11 Themes from a site (L3.5, R-MCP-12) — the network contract as built
`template_from_site {url, wait_s}` (MCP; job kind `site`, workspace-level, no project) and `retake theme from-site
<url>` (trust `author`, in-process, never a job). Spike (2026-10-19, Chromium 1194 / playwright-core 1.56.1): the
CONNECT-proxy design of the L3.5 critique holds — a local self-signed site on `.test` names (apex → www redirect,
cross-host image redirect, `@font-face`, WebSocket, POST, a service worker through `ServiceWorkerContainer.prototype
.register.call` and from a fresh iframe, preconnect, STUN to a local UDP port) loads with zero hits on the escape
listeners, and the reserved example domain loads over h2 through the proxy; Chromium's own background requests reach
the proxy and are refused (absolute-form GET, unannounced CONNECTs).

- **URL** (core `site.ts`, `parseSiteUrl` → `{href, host, unicode_host}`, at submit and in the worker): `https:`,
  default port, no userinfo / query / fragment (checked on the serialised href: `?` / `#` alone count), path ≤ 200,
  URL ≤ 300, no control character or backslash, a DNS name with a dot (one trailing dot stripped), no IP literal (the
  WHATWG parser canonicalises decimal / octal / hex / short IPv4 first; brackets refused), no suffix of
  `SITE_RESERVED_SUFFIXES` (localhost, local, localdomain, internal, intranet, lan, home, corp, home.arpa, arpa, test,
  invalid, example, onion, alt), no all-numeric last label. Canonical href = `https://<punycode host><percent-encoded path>`.
  Engine `siteHostConflicts`: the host equal to an environment page's host of any workspace project, or a protected
  host (`protectedHostOf`, patterns included) — refused through MCP, a warning in the CLI. Subresources are not checked
  against environments. `SiteJobInputSchema` (core `jobs.ts`): `{version, kind: 'site', site_id: s_<ULID>, url (refined
  by siteUrlProblem), submitted_by, approvals}`.
- **Approval** (engine `approvals.ts`): `SiteApprovalRequest {href, host, unicode_host, fingerprint, fix}`,
  `Approver.approveSite?`; `takeSiteApproval` → `[{fingerprint: sha256("site\n" + href), by: human-elicitation}]`,
  signed at enqueue (signing.ts, HMAC over the whole input). No approver / no `approveSite` → `needs_approval`;
  decline, dismiss, timeout, error → `refused`; both with `retake -C <ws> theme from-site <href>`. The MCP form
  (`siteApprovalMessage`) shows `URL: <href>` and `Host: <unicode host> (written <punycode>)` — never the decoded path.
  The worker (`executeSiteJob`) refuses the WHOLE job unless `verifiedApprovals(input)` holds that fingerprint
  (independently of the worker's generic filtering), whatever `submitted_by` says; then the URL and the environment
  hosts are checked again and the worker makes the extraction's folder (`makeSiteDir`: `.retake/` and `site/`
  real folders inside the workspace, never links; `<id>/` made non-recursively — an existing one, planted, refused;
  nothing is reserved at submit). Limit: the signature has no nonce or expiry (as hooks jobs): a copied job.json
  replays the same approved URL (BL-75).
- **Network** (runner-web `site/proxy.ts`, `site/extract.ts`). Chromium: `launchTarget`, headless, `--proxy-server=
  http://127.0.0.1:<proxy>`, `--proxy-bypass-list=<-loopback>`, `--host-resolver-rules="MAP * ~NOTFOUND, EXCLUDE
  127.0.0.1"`, `--webrtc-ip-handling-policy=disable_non_proxied_udp` (the `force-` variant does not stop STUN),
  `--disable-quic`, `--disable-blink-features=SharedWorker,FetchLaterAPI`; context 1440×900 @1, `reducedMotion`,
  `serviceWorkers: 'block'` plus `SERVICE_WORKER_BLOCK` (an init script making `ServiceWorkerContainer.prototype
  .register` reject, non-configurable, in every frame) and `UNROUTED_APIS_BLOCK` (`SharedWorker` and `fetchLater`
  that throw, non-configurable, every frame: a shared worker's requests and a deferred fetch — sent once the page is
  gone — never reach the route, no method check, no cap; measured: a fetchLater POST reached the fixture before; so
  both are removed twice),
  `acceptDownloads: false`, `routeWebSocket(/.*/, close)`, `ignoreHTTPSErrors` only with the test resolver (then for
  every host of the context: Playwright has no per-host switch). Route (`requestUrlProblem`): `https:`, port 443, a DNS
  name not reserved, GET / HEAD, ≤ 300 requests — else aborted and counted (`blocked` by reason, URLs under
  `untrusted`); main-frame navigations after the first document, and every navigation of another page (a popup: its
  request has no frame yet) → `fulfill 204`; allowed → `proxy.announce(host)`, `continue()`. Time: every call into the
  page (CDP evaluate, screenshot, a candidate's GET or body, the raster page) is raced against `SITE_CALL_TIMEOUT_MS`
  (15 s; the CDP detach is not awaited), the extraction against `SITE_DEADLINE_MS` (120 s), and the caller's signal;
  the deadline or the signal close the browser at once (a renderer busy loop cannot hold the worker): deadline →
  report `failed`, signal → `CancelledError` (job `cancelled`). Files: written under `.<file>.<hex>.tmp` with `wx`,
  renamed into place (a planted link is replaced, never written through); the out folder must be a real folder. Proxy: one `CONNECT <name>:443 HTTP/1.x` per client (head ≤ 8
  KB), absolute-form → 403 `request`, IP literal / numeric → `ip_literal`, port ≠ 443 → `port`, not announced →

### 2.1 Planner rules (SPEC §9 + reference look)
- Order: intro (unless disabled) → scenes / cards / interstitials in scenario order → outro. Every segment carries its
  ResolvedComponent: override by segment id → override by kind → scenario → theme → built-in default. A clip's caption
  resolves by kind (L4.5): `overrides.components.caption` → the scenario's `caption_component` (`timeline.video`,
  re-planned from today's file like every edit value) → theme → built-in default; `overrides.captions: false` still
  turns captions off. Per-scene caption components are not a scenario key (BL-107).
- Scene source range: from the end of the scene's page load (`scene_still`.t_start, else `scene_open`.t_end, else
  scene.t_start) to scene.t_end (includes trailing holds). Page loads are never shown.
- Transitions: scenes NOT contiguous in the capture (page load or any gap) use the theme transition (crossfade 0.35 s:
  outgoing clip holds its last frame while the incoming one fades in). Scenes contiguous on the same page are joined
  with NO transition (only the caption changes; camera continues). Intro→first scene and last scene→outro use the theme
  transition. Interstitials: backdrop = dimmed last frame of the previous clip (`backdropSrcFrame`), fade in/out.
- Speed: scene speed (overrides.speeds wins), step speed for its span; always 1×: the opening still, every hold
  (action and modifier), ±0.6 s around a marked step through its hold end (a marked `wait_for` /
  `wait_for_email`: only around its end — the moment the awaited state appears). Speed changes are ramped over ~0.3 s.
- Waiting (L2.12, `timing.ts` `waitingSpans`): the time a `wait_for` / `wait_for_email` step spends waiting — plus the
  pause after a navigation that precedes waits which really waited (≥ `WAIT_LOADING_MIN_S` = 0.3 s) — is a loading
  state: after its first `WAIT_KEEP_S` = 0.5 s it plays at up to `WAIT_SPEED` = 4× (only spans ≥ `WAIT_MIN_S`; a step
  speed wins; protected spans stay 1×; `overrides.trim_idle: false` disables it and gives a marked wait step back its
  whole 1× mark window). Noted per scene when some of it plays faster (none when a mark or a hold covers it). This is the root
  cause fix of the catalogue's `long-wait` warning: the import's 3.8 s loading spinner was protected at 1× by its
  marked wait step.
- Quick month runs (R-CHO-24, L1.2; `timing.ts` `quickRunSpans`, `planRunTiming` input `quick`): the `data.quick_runs`
  of a `date` step (≥ 5 month clicks ~110 ms apart), from 0.1 s before the first press to 0.35 s after the last (its
  ripple), play at up to `QUICK_RUN_SPEED` = 3× — ramped like any speed change, so a short run never reaches the full
  speed —; a step speed wins, protected spans stay 1×, `overrides.trim_idle: false` disables it. Noted per scene when
  some of it plays faster ("month run a–b of the capture played at up to 3×"; none when a mark or a hold covers it).
- Held page loads (R-ISS-08, L1.2; `timing.ts` `planRunTiming` input `loading`): a page load the capture held
  (`timeline.loading` — a multi-page run uses its pages' `tracks[].loading`) of ≥ `LOADING_CUT_MIN_S` (0.15 s, core)
  is cut whole, `[t_start·fps, ceil(t_end·fps))` — up to the first source frame of the painted page —, inside
  protected spans too (a frozen frame is never what a mark or a hold shows); `RunCut.reason: 'loading'`, noted
  ("page load a–b of the capture cut"); off with `overrides.trim_idle: false`. A multi-page run's time map is shared
  by its pages: a load held on one page is cut only where no other page acts (`loadsBesideOtherPages`: another page's
  step through its hold, ±0.6 s around a marked one, the opening still) — that page keeps its previous frame
  meanwhile; the runner never starts a step while any page of the scene is held. A page change inside a held load —
  or up to `LOAD_START_SLACK_S` (50 ms) before its start: the URL segment and the hold come from two listeners of the
  same commit — counts from the load's end for `waitingSpans`. Timing shift (L1.2): the paint wait of a navigation is in the navigating
  step now, a `wait_for` after it waits less — the wait compression sees less, the cut takes its place.
- Idle trimming: the part of a timeline.idle interval outside the protected spans (still, hold, mark window) and the
  held page loads, when longer than `idle_threshold` (1.2 s), is shortened to 0.4 s (0.2 s kept on each side of the
  cut; `RunCut.reason: 'idle'`). Nothing changes on screen during idle, so the trim is invisible.
- Camera: static by default. Zooms only from step `camera` hints: zoom clamped to theme max_zoom, focus = event
  camera bbox centre (else point, else cursor), eased with the hint's `ease` (else the theme zoom_ease) from the
  step's output start over max(0.8 s, duration) of OUTPUT time (duration defaults to the step's output length),
  held until `until` (default scene end), same easing out; the view is clamped so the capture always fills the screen
  rect; no reset at same-page joins.
- Captions: scene caption from the scene's first visible frame to its end; a step caption replaces it from the step's
  output start; cues never overlap. Rendered by the clip's caption component in the layout's caption rect.
- Overlays: from step `overlay` modifiers (`event.overlay`), shown from the step's output end for `duration` (else the
  component's default), anchored on `overlay.bbox` (else `overlay.point`) mapped through layout + camera. A file
  overlay (L2.12) starts at its `at` and fills its `box` (§1.9).
- Provenance: every clip segment lists `steps` (output frame spans per scenario step) and the plan keeps markers and a
  time map — used by review, the Studio timeline and frame comments.
- URLs (L1.7, R-ENV-01): `ClipSegment.urls` / `PlanPane.urls` hold what the browser bars show — each real URL of the
  timeline (`pages[]`, `tracks[].pages[]`) mapped through the edit's display table (core `displayUrl`), recorded as
  `plan.display`: display URLs are edit-time data — core `editDisplayTable(timeline.environment.display,
  displayRows(project's environment))`, the environment being `timeline.environment.name`, else `PlanEditInput.env`
  (run.json `env`, passed by render / plan / still: runs captured before L1.7 get the project's display URLs too); the
  project's current rows win, recorded rows for real bases it no longer declares are kept. A URL
  still local afterwards (core `isLocalUrl`: no display URL for its page) is kept with
  `hidden: true` — `urlAt` / `paneUrlAt` return undefined there (the bar shows no address; window bars fall back to the
  theme's `brand.url`), the entry still marks the navigation for the review — and, when the clip's layout draws a URL
  (`drawsUrl`: studio/layout-browser unless `show_url` and `tabs` are both off, split / pip with `chrome`, the pip's
  main page only), a plan warning per page ("page "shop" has no display URL (http://localhost:4402)… add display: to
  environments.local.shop in project.yaml and render again"; a URL outside the environment's pages: "a local URL
  outside the pages of environment local…"). Notification
  media `app` = the display host of the notification's origin (a local host without one: the theme's `brand.name`).
  Captions, cards and the other edit text were templated by the runner with the display URLs (core
  `templateSceneEntry` edit context).
- Output: 1920×1080 × scale (capture scale 2 ⇒ 4K; a scale above the capture's is a warning: the capture is
  upscaled); vertical 1080×1920 / square 1080×1080 use `geometry_vertical` / `geometry_square`. When the screen rect's
  aspect differs from the capture's, `PlanLayout.crop` is the region of the capture with that aspect (narrowed so the
  capture shows at ≥ `REFRAME_MIN_SCALE` = 0.9 design px per CSS px) and `ClipSegment.reframe` its centre per frame
  (L2.8, camera.ts `reframeTrack`): the region of interest = the cursor box (+ where it goes in the next 0.4 s), the
  active step target from 0.5 s before the step (look-ahead), hard boxes (each click's target from 0.35 s before to
  0.5 s after the click — widgets: every `data.clicks` entry —, overlay anchors while shown) — their union while it
  fits; a dead zone (15 % inset) and re-centring; critically damped zero-phase smoothing (two first-order lags of
  τ = 0.2 s forward and backward); then `corridorSmooth`: the closest path inside the per-frame corridor where the
  cursor box and the hard boxes are in view, as a banded QP (Σ d² + 2L² Σ (Δd)² + L⁴ Σ (Δ²x)², L = 0.3 s: a critically
  damped repair — no ringing, no wrong-way move — solved with ADMM); finally inside the capture. Per run: never across
  a cut. `viewOf` / `mapSourceRect` give the visible region / map overlays through it.
- Theme default zoom (R-ED-22, L2.8): `motion.default_zoom` > 1 with style_bias balanced / motion → in each scene
  without its own camera hint, one zoom (min(default_zoom, max_zoom)) on the first marked step's target (camera bbox,
  else target bbox, else overlay anchor, else point), eased in over min(4 s, half the room) from that step's output
  start with the theme `zoom_ease`, eased out over min(1.6 s, a quarter of the room) so the scene's last frame is at
  1×; no zoom when the room is too short (< 1.5 s in, < 0.8 s out: note). `ZoomSpan.source = 'theme'`. Real → static
  (note when default_zoom is set).
- Music (R-ED-17, L2.8): `PlanMusic {volume (0.6), duck (0.5), duck_ramp_s (0.5), fadeIn_s 1, fadeOut_s 2, loop
  (true), crossfade_s 1, duration_s?, plays?}`; `plays` (when the caller measured the track): one play trimmed by the
  video (longer track or loop false) or loops each starting `crossfade_s` before the previous ends. Volume at frame f
  (`musicVolumeAt`): volume × smoothstep fades × (1 − (1 − duck) × on-clip), on-clip eased (smoothstep) over
  `duck_ramp_s` around each clip; each play × an equal-power seam gain (`musicPlayGain`).

### 2.2 Composition & rendering
`DemoVideo` / `DemoVertical` / `DemoSquare` (Remotion, `packages/editor/src/remotion/`) take `{ plan }` and render only the plan:
background, one Sequence per segment with its transition component (every fade is one — a plan whose fade carries no
component gets the transition stand-in, like any missing component; the composition draws no fade, colour or text of its
own, test-guarded: no colour literal in `src/remotion/`), the segment component, for clips the layout component with `screen` = the capture frame `srcFrames[f]` under the camera
transform and `rects` = the clip's PlanLayout in output px, the caption component (cues, `area` = the layout's
caption rect, `rects` = the layout's rects) and overlays (anchor mapped per frame with `mapSourceRect`, `rects`), the brand mark (theme logo + wordmark in the layout's `brandmark` rect — layouts do not draw it; the one visual the
composition places itself, R-CMP-01 exception: see below),
optional music bed (one `Html5Audio` per planned play, volume = bed volume × seam gain; without plays the element
loops itself). Interstitials receive the previous clip's last frame (layout + capture + brand mark) as `screen`. The
capture `OffthreadVideo` is drawn with `object-fit: fill` in a box of the visible region's aspect scaled to the capture's
(a reframe crop is never letterboxed).
**R-CMP-01 audit (L2.14).** Everything the edit shows is drawn by a component, except two theme-driven elements the
composition places itself: the theme **background** behind every segment (`backgroundCss(theme)`, the theme's own
token) and the **brand mark** (the kit's `Logo` + `Wordmark` — the same primitives components use — sized, placed and
faded by the theme's `brandmark` settings in the rect the layout component declares). They stay in the composition
because they are one layer for every layout (the mark above the screen-layer overlays and under the caption,
interstitial backdrops included) and they are theme tokens, not a look of their own: a theme changes them, a layout
that declares no `brandmark` rect gets none (and may draw its own). No colour, text or shape is hard-coded.
Transitions render twice: a crossfade over the overlap of the two segments (both see transition frames [0, n)), a dip
without overlap (frames [0, ⌊n/2⌋) at the end of the outgoing segment, [⌊n/2⌋, n) at the start of the incoming one).
The capture frame is an `OffthreadVideo` inside a `Sequence` shifted to that frame — not `<Freeze

**Edit without re-capture (L5.5; replaces the L3.8 rule "a render shows the run as captured").** The capture comes from
the run, the edit from today's scenario file while the scenario's **filmed part** is unchanged since the capture.
Core `filmedChanges(now, then)` (`filmed.ts`) compares the filmed part of two scenario texts as data (core parseYaml;

`cursor`; each step's fingerprint (core stepFingerprint: action + normalised arguments) with `hold`, `park`, `on`.
`timeout`, `optional`, `irreversible` and `note`s are left out; everything else is edit. The result is a list of
trusted words (keys, scene ids, step keys `scene.index` by a longest common subsequence: "scene send: step send.2
changed, 1 step removed", "the setup hooks", "vars the take uses: company"); undefined when a text does not parse.
`scenarioSinceRun(project, runDir, scenario)` reads `scenarios/<name>.yaml` (else `.yml`) and the snapshot
`<run>/scenario.yaml` without following a link and without blocking — a regular file of at most

— and returns both texts, `changed` (any data change) and `filmed`.

camera. Capture times, cursor, pages, target boxes, artefacts, tracks and the environment are the take's. A value equal

### 2.3 Component previews (L2.7)
`ComponentPreview` is a third composition of the render bundle (`{ preview: ComponentPreviewSpec }`, see
`src/remotion/preview-types.ts`): one component in context — intros, outros, cards alone; a layout with a neutral
sample screen (`packages/components/preview/screen-{desktop,tablet,phone}.jpg` + `samples.json`: size, the address a
browser shows, a button the overlay previews point at — generated once from the fixture by
`scripts/preview-samples.mjs`, never needing a running app) as its capture, the brand mark and the theme's caption
(`studio/caption-overlay` when the layout's caption area lies over the capture); captions, overlays and transitions
around the theme's layout with that screen (a transition from that scene into the theme's card, which is shown
settled); interstitials over it as their backdrop. The spec is built in Node by `buildComponentPreview` (pure: the
manifest's preview slots + theme slot defaults, its params, the geometry evaluated with the sample's aspect,
`preview.screen` picks the sample) at the manifest's last `preview.at` second. `renderComponentPreviews` opens ONE
bundle (the targets, the context components and the scaffolds), one asset server and one browser, renders each still
at half scale (960×540; Remotion `scale: 0.5` on the 1920×1080 composition, so the layout is exactly a video frame's)
and palette-quantises it with ffmpeg when the full-colour PNG exceeds 200 KB; in place it writes `preview.png`,
`preview.json` (`PreviewMeta`) and the README block. Bundles ignore `preview.png` / `preview.json` in their hash
(regenerating previews never rebuilds a render bundle). The theme defaults to the `editorial` starter (a workspace
template of the same name wins); `--theme` renders with any template.

**Through MCP (L3.2).** A `preview` job of the engine (`jobs/preview-job.ts`; `component_preview`, `template_preview`)
calls `renderComponentPreviews` with `outDir: <workspace>/.retake/previews/<preview_id>/` — never in place, so the
committed previews, preview.json and README blocks stay a `retake components preview` matter — with per-target
overrides: `slots` (merged over the manifest's preview samples; the engine admits text, url and color slots only —
file and media slots keep their samples), `params` (merged over the preview params, validated against the schema by
the engine), `at`, and the image's `file` name (`intro.png`… for a theme). `network: 'guard'` arms the render's
network guard on the previews' browser (§2.2), `onBrowser` lets the worker record the browser (a killed worker's next
one kills it), `onWarnings` receives the blocked origins, and `signal` is checked before each still
(RenderCancelledError). The theme is a name or the project's own; its logo, wordmark and fonts must lie in its folder.

renders the poster (the still, 960×540 under 200 KB) and / or the loop — GIF 640×360 at 15 fps (every second frame),
playing forever, at most 6 s, of the motion spec; over 1.5 MB again at 480×270, still over → `{too_large}` — into the

### 2.4 Raw export for editors (L2.13)
Capture-side, so it lives in `@retake/runner-web` (`src/raw/`): it owns the screencast frames, the CFR schedule
and the kit's cursor look. `exportCapture({project, runDir, template?, format, fps, cursor, layer, selects, cuts, out,
editFiles})` → `<project>/exports/<run-id>-raw-<format><fps>-<cursor>/` (written as `<dir>.partial-<pid>`, swapped in).
CLI `retake export-capture <project> <run|latest>` and `retake run … --raw` (packages/cli/src/commands/export-capture.ts;
the CLI resolves the run with the editor's `findRun`, loads the run's template for the cursor look and lists the edit's
own files with `planFileRefs` / `themeFileRefs`). project.yaml `raw` (core `RawSettings`) holds defaults; flags win.
- **Clip plan** (`plan.ts`, pure): one clip per captured scene, one per page of a multi-page scene (same spans; the
  page of the opening still is `primary` = on the sequence). Range `[scene_still.t_start (else the last scene_open's
  end), scene.t_end)` — the page load is never in a clip; on the export grid frame n = capture time n / fps,
  `[ceil(s0·fps), ceil(s1·fps))`. `loadingCuts`: each run of wait steps (`wait_for`, `wait_for_email`, same page,
  stopping at a marked wait or one with a hold) that waited ≥ 0.3 s is cut from `action_keep_s` (0.3 s) after the
  LAST press of the contiguous step before it (`actionMoment`: the latest of `t_click`, each `data.clicks[].t_click`
  — a select's option, a menu's item / confirm, a pick's close —, `t_typed`, `t_enter`; a drag, repeated keys and
  typing without `t_typed` are kept whole: their end) — or from that step's URL change after that press when it
  navigated earlier (nothing of the loading page kept; a URL rewritten while typing is no navigation) — to the last
  wait's end + margin, margin = max(0.2 s, min(0.3 s, 1.5 × the capture's local screencast interval)) — new content
  reaches the screen up to ≈ 0.2 s after its DOM (L1.3) —, then snapped to the next screencast frame of that page
  when one arrived within another margin (the page was still painting:
  the frame on screen may be half drawn — seen at 60 fps on the catalogue import, ≈ 8 fps under a backdrop blur; an
  idle page sends no frame, its last one is final). So the first frame after the cut is a frame painted after it, at
  any export rate. A cut must leave ≥ `min_tail_s` (0.2 s) of its scene after it: a scene that ends on its awaited
  state keeps its loading (a note says so — add a `hold`), else the result would be in no clip. Never into the
  opening still, a hold or a marked step; ≥ 0.4 s or not at all; reasons `navigation`, `loading`, `mail`. A **held
  page load** (R-ISS-08: `timeline.loading`, or the scene's pages' `tracks[].loading`; option `held`) clipped to
  `[clip start, scene end)` is a `navigation` cut from its commit to its end (the first frame of the painted page) from
  `LOADING_CUT_MIN_S` (0.15 s — the cut sits on the page change, where the picture changes anyway), inside the still, a
  hold or a mark too; it has no `wait_step` (manifest and markers: `after_step`, the step during which the page
  changed); one overlapping a wait-based cut extends that cut; one reaching the scene end is cut up to it, as the edit
  does (noted "the scene ended before the new page painted"). A multi-page scene's clips share their frames: its held
  loads are cut only where no other page acts (`heldBesideOtherPages`: another page's step through its hold, the
  opening still). Timing shift (L1.2): a
  navigating click now includes the paint wait, so the `wait_for` after it often waited < 0.3 s and makes no cut — the
  held-load cut replaces it (raw-real: `{navigation, after_step: 2}`, no `wait_step`). Markers at
  the very end of a scene land on the clip's last frame (never dropped). Clip names `NN-<scene>[-<page>]`. `clipFrameAt` maps capture times (a time inside a cut → the
  frame after it); the sequence = the primary clips back to back.
- **Encoding** (`encode.ts`): `cfrSchedule(frames.jsonl, duration, fps)` at the EXPORT rate (60 fps = the
  screencast's real timing, up to 60 frames/s when the page moves — never interpolated), the clip's frames hard-linked
  as a sequence, encoded once from the JPEG/PNG frames: MP4 = libx264 high, CRF 14, preset medium, GOP = 1 s,
  yuv420p, faststart; ProRes = `prores_ks` profile 3 (422 HQ), yuv422p10le, `.mov`; BT.709 limited (JPEG full-range
  BT.601 converted); `-timecode` = the clip's sequence position (tmcd track in both containers). No frames kept →
  the CFR video decoded once (its tagged matrix → full-range JPEG) and repeated, with a note. Each output ffprobe'd
  (frames, codec, profile, pix_fmt, timecode) into the manifest. Selects: the primary clips concatenated by stream copy
  (skipped with a warning when their sizes differ).
- **Cursor** — runner: `RunOptions.hideCursor` (CLI `run --raw --cursor none|layer`) → `KitConfig.cursor.hidden`: the
  kit adds `.c,.rps{display:none}` (the file-drag ghost card stays — page content); real input, the Node cursor track
  and everything else unchanged; `timeline.capture.cursor: 'hidden'`, `run.json options.cursor`; the cursor-motion
  frame-rate warning is skipped (a hidden cursor's move changes nothing on screen). In every run the kit now reports
  what its cursor draws through the binding `__retakeCursor` (`effect()`: `icon` on every change and the first
  one of each document, `press` / `release`, `ripple` at x, y) → `Runtime.cursorEffect` → `timeline.cursor_effects`
  for the main capture's active page, `tracks[].cursor_effects` while a track records (plus the current icon when a
  page starts being filmed: `currentIcon`). `cursor.ts`: `cursorFrames` (per clip frame: the latest sample at n/fps,
  last icon, press scale = the kit's 90 ms ease-out to 0.9, ripples younger than 550 ms — `CURSOR_LOOK`, a test keeps
  it equal to the kit's CSS), `approximateEffects` for runs before L2.13 (presses / ripples at button-down samples and
  synthetic clicks, the hand over a running step's clickable target, the text beam over a field), `clipClicks`
  (`data.clicks` of widgets, else the step's click) → `cursor/cursor.json|csv`, `clicks.csv` in clip pixels.
- **Cursor layer** (`layer.ts`): `renderCursorAtlas` evaluates `kitSource` in a blank Chromium page, reads
  `api.cursorLook` (the overlay's stylesheet + markup, the same strings the kit draws with) into open shadow roots, one
  cell per icon × press-scale step (11) and per ripple age (1/120 s, animations paused at that age), one transparent
  screenshot at the capture's device scale decoded by ffmpeg; `encodeCursorLayer` blits the sprites (straight-alpha
  over, ripples under the icon) into a reused RGBA frame per clip frame and pipes it to ffmpeg: ProRes 4444
  (`prores_aw` profile 4 — ≈ 5× faster than prores_ks on these mostly empty frames, alpha within 1/255 measured) or
  VP9 + alpha (`.webm`). Frame-aligned with its clip by construction (same frame list, fps; ProRes: same timecode).
  WebM cannot carry a timecode (Matroska): its media time starts at 0 — the OTIO references it from 0, the FCPXML
  leaves it out (Final Cut Pro does not read VP9), the package README and a note say `--layer prores` is the one for
  editing tools. The manifest names no pixel format in the layer codec label: each layer's `pix_fmt` is what ffprobe
  reads back (ProRes 4444 decodes as yuva444p12le).
- **Markers** (`markers.ts`): `rawMarkers` on each scene's sequence clip — scene (chapter), caption (until the next),
  step (its span; page named in multi-page scenes), mark (a wait's end, a click's press, else the start), cut —
  colours BLUE / YELLOW / GREEN / RED / MAGENTA. `writeFcpxml` (1.10: a format per clip size, an asset per clip and
  layer with `start` = its timecode and a `media-rep`, one event / project / sequence `tcStart="0s"`, spine of
  asset-clips; inside each, connected clips — its layer lane 1, other pages and their layers enabled="0" — then
  `chapter-marker` / `marker` with notes; every time N/fps s), `writeEdl` (CMX 3600 NDF, reel `CLIP<nnn>`, `* FROM CLIP
  NAME` / `FROM CLIP`, `* LOC: <tc> <COLOUR> <KIND>: <name>`; one picture track: other pages and layers are left to
  FCPXML / OTIO), `writeOtio` (OTIO 0.17/0.18 JSON: V1, Cursor, Page n [+ cursor] tracks, Gap fillers, Clip.2 with
  ExternalReference with a `file://` target_url and available_range at the timecode — 0 for WebM layers —, Marker.2
  with colour / comment / metadata), `markersCsv|Json`. URLs in step markers and click targets (L1.7): `exportCapture`
  maps the events' target descriptions through the edit's display table (`exportDisplayTable`: core
  `editDisplayTable` of the timeline's table and project.yaml's current pages of the run's environment) with core
  `shownText` (`2. open https://shop.example.com/quotes`, a local URL without a display: `2. open /quotes`), in memory —
  the run's timeline.json keeps the real URLs.
  Checked with OpenTimelineIO 0.18.1 (otio_json, cmx_3600 and fcpx_xml adapters): `scripts/validate-raw.py` (L2.14,
  optional, not a repository dependency).
- **Manifest** (`RawManifest`, `manifest.json`) + `README.md` (`packageReadme`): run, settings, sequence, clips
  (measured), selects, cursor files and icon source, marker files and counts, the edit's own files, notes, warnings.
- **Editor**: a hidden-cursor capture still plans and renders, with a plan warning (no cursor in the video).
- **CLI JSON**: `export-capture --json` prints the manifest (one document); `run --raw --json` keeps stdout JSON

## 3. Review (`packages/review`)

```ts
reviewRender(opts: { project; render: string; fps?: 1 | 2; previous?: string | false }): Promise<ReviewResult>
```
Writes `review/<render-id>/`: `sheet_<fps>fps.jpg` (+ pages), `sheet_scene_<id>.jpg`, `keyframes/<marker>.png` (the
screen once the marked step is done — `plan.markers[].done`, a marked wait's awaited state; L2.14)
(+ scene first/last), `timeline.json` (output-time: segments with components, captions, markers, step spans),
`report.json`, `report.md`; returns ≤1280 px JPEG thumbnails (base64) for the MCP. Checks: durations; blank/near-uniform
frames in the screen rect and at scene starts; caption/scene mismatch, overlaps, captions too long for their area;
text slot overflow; cursor off-screen or outside the zoomed view at clicks; scenes > 30 s at ~1×; zoom count and resets
at same-page joins; transitions overlapping a click; diff vs the previous render. Findings:
`{ severity, code, message, at?: { frame, time, segment, scene, step } }`; `clean` = no error/warning.

Implemented in L2.6 (`packages/review/src/`; options also `scenario?` with `latest`, `thumbnails?: false | 'sheets' |
'all'`, `thumbnail_px?` ≤ 1280, `rules?` = thresholds, `sheet?` = grid, `out?`):
- **Inputs**: the RenderRecord (its plan is the truth: segments, evaluated layout rects, cues, step spans, camera,
  srcFrames, markers), the video, the run's `timeline.json` (clicks, cursor track, captions as captured; optional) and
  the capture (scene starts; optional). Spans: a segment is "visible" over `[from, next.from)` (a crossfade counts with
  the incoming segment); `clearFrom/clearTo` exclude the transition windows (`transitionWindows`).
- **Frames**: one ffmpeg pass per video with a `select` on exact frame numbers, raw RGB streamed with back-pressure
  (`extractFrames`): the render (contact sheet samples at the middle of each 1/fps interval, 2 fps scene samples, key
  frames, the opening-still pair of each clip), the capture (first frame of each clip + capture frames behind blank
  samples), the previous render (same segment, same offset). sharp makes tiles, sheets (labels in one SVG per page) and
  key frames; statistics are plain JS on the RGB buffers (share of pixels near the median colour, luminance sd, 96×54
  luminance signatures).
- **Text widths** use the theme's real font files (`fonts.ts`: cmap + hmtx of TTF/OTF/WOFF, no kerning) with the kit's
  `fitText` (now exported from `@retake/components`), so "too long" matches what the caption component draws.
- **Severities**: video length outside 1–2 min = info within ±25 % (45–150 s), warning beyond (the range is a style
  target measured on two reference videos); scenes outside 4–25 s = info, < 2 s = warning; > 30 s at 0.85–1.2× =
  warning; blank screen ≥ 1 s or at a scene start = error; caption cut = error, shrunk below 85 % = warning; cursor off
  screen / outside the zoomed view at a click = error; more than one zoom = warning; transition over a click = warning;
  diff findings are info. Added beyond the brief: `long-wait` (an unchanging screen ≥ 3 s while the scenario waits —
  wait steps and the time after an action until the next step, holds excluded: catches loading skeletons that idle
  trimming cannot), `loading-scene-start` (the screen changes during the opening still), `empty-segment`,
  `caption-not-visible`, `caption-overlaps-brandmark`, `camera-jump`.
- **Output** is written to `review/<id>.tmp-<pid>-<hex>` and swapped in, so a review never mixes pages of two runs.
  L3.2: the swap sets the previous review aside (`<id>.old-<pid>-<hex>`) before renaming the new one in, then removes
  it; `recoverReviewDir(dir)` (run at the start of every review, and by the jobs worker after a killed review job)
  brings an aside review back when no review took its place and removes the temporary folders of dead processes — a
  crash between the two renames never loses the previous review. `signal` (L3.2) cancels: checked between stages and
  passed to ffmpeg (`extractFrames` kills it); a cancelled review throws `ReviewCancelledError` and the previous review
  is untouched. `reviewImages(files, {fps, markers, mode})` is the image list (contact sheet pages + marker key frames;
  `all`: every key frame, scene sheets, the diff sheet) — the thumbnails and the MCP's `review_get` both use it.
- **Through MCP (L3.2)**: a `review` job (engine `jobs/review-job.ts`) runs `reviewRender` with `thumbnails: false`
  (no image data in job.json); `review_get` (engine `reviews.ts`) reads report.json as data and rebuilds every path
  from `review/<id>/` (a known file name of that folder, symbolic links resolved inside it), lists the images with
  `reviewImages`, and the MCP server makes JPEG thumbnails on read (`thumbnailOf`, ≤ 1280 px; ≤ 4 images and ≤ 1.5 MB
  of base64 per result, the rest as paths). Finding messages, the environment and the diff's per-segment changes go
  under `untrusted`. Nothing else of report.json is copied as is: a finding code shows only when a check writes it
  (`FINDING_CODES`, kept complete by a test), segment / scene ids only when they match the name pattern of the review's
  files, a component id and the previous render id only when they match theirs (else `unknown`, the original under
  `untrusted`), and the keys of key frames and scene sheets are re-derived from their rebuilt file names. Job tools
  (`job_status`, `job_list`, `job_cancel`, `export`) return a run, render, preview, review or export job's error
  message only under `untrusted.error` (a placeholder in `error.message`, never in the summary) — an interrupted job's
  message, written by the engine, excepted.
- **L2.8**: clicks are placed one by one (widgets: every `data.clicks` entry, with the box it clicked); reframed
  variants: `target-cut` (error: the reframe cuts a clicked target that fits in the view), `cursor-outside-view` at
  clicks (error, "vertical reframe"), `cursor-outside-reframe` (warning: the cursor leaves the crop on any frame),
  `reframe-jump` (warning: a move > 6 % of the crop width in one frame or a jolt > 1.5 % per frame², rules
  `reframe_max_step` / `reframe_max_accel`); theme zooms are not counted against `max_zooms` but checked per scene:
  `theme-zoom-count` (> 1 in a scene), `theme-zoom-cut` (not back to 1× when the scene ends), `theme-zoom-real`
  (style_bias real); caption widths use the kit `captionMaxLines` of the variant.
- **L1.7 (environment)**: `ReviewResult.environment` (`reviewEnvironment(timeline, plan)`: name, production, access,
  allow_writes, clock, display bases, write counts — the automated sign-in's excepted) → the line under the title of
  report.md and on the terminal (`environmentLine`: "production · production · read-only · 1 write mocked · clock
  2026-11-02T10:24:00"). `checkEnvironment`: `write-blocked` (warning; one per method + origin + path of
  `environment.writes` with outcome blocked, at the first output frame showing its capture time, or unlocated before
  capture time 0 / outside the video), `url-hidden` (warning; a clip or pane whose layout `drawsUrl` with a `hidden`
  URL entry, at its frame), `local-url-text` (warning; core `findLocalUrls` in caption cues, kickers, every segment's
  and overlay's slots, pane labels; named by their path). URLs are named through `plan.display` (the table the render
  used), else `timeline.environment.display`. Findings never name a local host: a hidden URL is written as its path
  "(a local page)" (a `file:` URL: its file name), a write by its display URL (`tutorial-stale-target` too), and every
  local URL in a plan warning is masked the same way (`plan-warning`); report.md's caption list quotes captions as
  written (a local URL there is a `local-url-text` finding).

## 4. Frame comments (L3.6: format, anchor, still, store, CLI and MCP tools built; L4.6: the Studio channel, render frames, counts, proposals, the Studio's comment ops, Comments screen and proposal view)

`<project>/comments/<scenario>/<thread-id>.json` — one file per thread (ADR-1 #4). Thread ids are `c_` + a ULID and
entry ids `r_` + a ULID (core `newCommentId` / `newCommentEntryId` over core `ulid`): unique across machines, sortable by
creation time. Entries (replies, resolutions, reopenings) are only appended, so two writers (git branches, a later sync)
only ever add entries; the status is **derived** from them (core `deriveStatus`: the last resolve or reopen entry
decides), never stored. Core `CommentThreadSchema` (strict zod) is the contract:
```ts
interface CommentThread {
  version: 1; id: string /* c_<ULID> */; scenario: string;
  render: { id: string; created_at: string; run_id: string; variant: 'landscape' | 'vertical' | 'square';
            fps: number; frames: number; width: number; height: number };   // the render as it was (ids get reused)
  frame: number; time_s: number;                                // 0 ≤ frame < render.frames
  region?: { x: number; y: number; w: number; h: number };      // 0..1 of the output frame, w, h > 0, inside the frame
  marker?: string;                                              // the frame was picked by a marker
  text: string;                                                 // ≤ 2000 characters, line breaks kept, no control / bidi / invisible
  author: { via: 'cli' | 'studio' | 'mcp'; name: string };      // the channel that wrote it, never "a human"
  created_at: string;                                           // ISO 8601 UTC
  anchor: FrameCommentAnchor;                                   // computed when the comment is made (below)
  entries: Array<{ id: string /* r_<ULID> */; kind: 'reply' | 'resolve' | 'reopen' | 'apply'; author: { via; name };
                   text: string; created_at: string;            // a reply / resolve has a text; a reopen / apply may not
                   render_id?: string; render_created_at?: string;  // a resolution: the render that answers it
                   proposal?: CommentProposal;                  // L4.6: a reply's proposed change (below)
                   applies?: string; scenario_sha256?: string }>;  // L4.6: an apply — the reply applied, the file written
}
```
Texts are sanitised once for every channel (core `commentText`: `\r\n` → `\n`, tabs → spaces, C0 / DEL / C1, bidi
controls and invisible format characters — zero-width space, word joiner and U+2060–2064, BOM, the tag characters
U+E0000–E007F that hide text a model still reads; ZWJ / ZWNJ stay — removed, then refused above 2000 characters — the
MCP's cap on an untrusted string); author names through core `printableText` (the same character sets, shared with the
brand inputs of L3.5), ≤ 80 characters. The schema refuses a stored text or name that still holds any of them.

**The anchor** (`FrameCommentAnchor`, review `frameAnchor(plan, frame, {region, scenarioText, timeline})`, pure, from the
render's plan): `segment` (the incoming one during a crossfade), `kind`, `component` (the segment's; a clip's layout),
and for a clip `scene`, `step` / `step_id` / `step_ref` (`<scene>.<step_id|index>`, the `--until` syntax) / `action`
(`scene_still` at the opening, no step), `step_fp` + `step_fp_n` (core `stepFingerprint` of the step in the run's
`scenario.yaml` snapshot: its action and normalised arguments, modifiers left out, a `hold:` action kept; `n` = its

**Proposals** (L4.6, R-UI-28; core `line-diff.ts`, `comments.ts`; engine `comment-proposals.ts`, `comments.ts`;

- Stored in a reply: `CommentProposal = {base_sha256, result_sha256, eol: 'lf' | 'crlf', delta: 'edit', hunks:
  Array<{at, del: string[], add: string[]}>}` — the sha256 of the thread's own scenario file it was made on and of the
  exact bytes Apply writes, and the **canonical** line diff between them (core `diffLines`: Myers' shortest edit script
  between the common head and tail; hunks 1-based on the base, sorted, separated by an unchanged line, never empty, no
  context). Lines are a text split at LF / CR LF without them (a final line break adds no line). The schema refuses a
  line with a control (a tab is fine), direction, invisible, default-ignorable or tag character, a BOM anywhere or a line
  break, a line over 2,000 UTF-16 units (the cap on one untrusted string: a longer line would be cut where it is shown),
  more than 200 changed lines (removed + added) or 30,000 characters of changed lines (critique B13), hunks out of order
  or touching, and `base_sha256 = result_sha256`. An `apply` entry names an earlier reply of the thread holding one. As
  for `studio`, a tool built before L4.6 reads a thread holding a proposal or an apply entry as invalid until restarted
  on the new build (critique B14: skipped with a problem, never overwritten).
- Written (`Engine.comments.reply(project, id, text, {proposal: {scenario_yaml, scenario_hash}})`, **client `mcp` (and
  `test`) only** — a `cli` / `ui` proposal is refused: the UI labels a proposal as Claude's; open threads only):
  today's file must have `scenario_hash` (else `conflict` with `details.current`); the file must not mix LF and CR LF;
  the text must not hold a lone CR or mix line breaks; it is split into lines and joined with the **file's** line break,
  a final one included (what `replace_text` writes); identical text, a text differing only by line breaks (zero hunks)
  and more than 200 changed lines are refused (`invalid`); a removed or changed line holding a hidden character is
  refused ("the person changes it in their editor"); then the Studio's own write checks without the write
  (`prepareScenarioEdit`, split out of `editScenario` — L4.3's tests are its regression net —, as `replace_text` with
  agent trust from the Studio: the file not blocked, no hidden character added, hooks and mocks unchanged, vars / env
  unchanged while there are some, no secret reference, no outside file, no agent-writable code, the scenario valid —
  warnings come back as `proposal_warnings`) and **edit-only** (`filmedChangesOf(result, today)` empty, else `refused`
  with `details.filmed_changes`: a filmed change is saved and captured, the direct loop — critique B2) with **no theme
  change** (`template:` as it is, else `refused` with `details.theme_change`: a theme takes the direct loop — review A
  L3). A line holding half a character (a lone UTF-16 surrogate: its UTF-8 bytes would be U+FFFD) is refused (review A
  L6), and so is a diff a person could not read whole: more than `PROPOSAL_ROWS_MAX` (600) rows with 3 context lines
  around each change (review A M1 — the Studio never cuts the diff). Refusals read "not proposed: …"; nothing is
  written.
- State (core `proposalStates(entries, todayHash)`, critique B4), from today's file first: `applied` (the file is its
  result — with or without an apply entry for the newest, only with one for an older proposal: review B L6), `undone`
  (an apply entry names it and the file is its base again: Undo apply), `superseded` (a later proposal), `stale` (the
  file is neither), else `pending`. Only the newest proposal,
  pending or undone, on an open thread is `actionable`. A thread view's entry carries `proposal: {state, actionable,
  delta, added, removed, hunks, base_sha256, result_sha256}` — never the lines (comments_list's budget is people's).
- The diff a person reads: `Engine.comments.proposal(project, id, entry_id?)` (default the newest) → state, counts,
  `rewrites_pct` (changed lines over both versions' lines: said past 25 %), `same_take` (pending / undone: the result's
  filmed part equals the commented run's snapshot — it renders on that take), and `rows` (`context` / `del` / `add` /
  `gap`, with base and result line numbers; texts parallel under `untrusted.rows`). The rows are **verified** when the
  engine rebuilt them from today's file (pending / undone: the file is the base; applied: the file is the result, the
  base the hunks undone) and checked (result / base hash, canonical hunks), with 3 context lines; otherwise the stored
  hunks, `verified: false`.
- Rebuilt for a preview or an apply (`rebuildProposal`, critique B1): today's file must be the base (`conflict`: ask
  Claude to propose again), of the stored line break; the hunks must apply strictly (core `applyHunks`: order,
  separation, removed lines equal to the file's — never a fuzzy patch), the bytes must have `result_sha256` and the
  hunks must equal `diffLines(base, result)` (`refused` otherwise: a thread file edited by hand).
- Apply (`Engine.comments.apply(project, id, {entry_id, if_match})`, the person channels `cli` / `ui`; `if_match` but for
  `cli`; refusals "not applied: …"): under the thread's lock, **held across the scenario write and the apply entry**
  (critique B5: thread lock → storage write lock; nothing takes them the other way — a reply with a proposal reads the
  scenario without the write lock): the thread read, `if_match` checked (before anything is written), open, the entry
  actionable (applied / superseded / stale are `conflict` with `details.state`), the text rebuilt and checked, the
  Studio checks and edit-only once more, then **`editScenario` itself** (`replace_text`, agent trust from the Studio,
  every L4.3 rule at the moment of the write, under the storage write lock), then the `apply` entry appended with no
  second hash check. The entry is checked to fit the thread (500 entries, 2 MB) **before** the scenario write — a full
  thread refuses with nothing written (review A L5 / B M3); a failure after the write (a real race) is a `problems`
  line, never a failed answer (the state reads `applied` from the file's hash). The proposal view runs the same checks
  before offering anything: `blocked` (Apply's refusal in words, project-relative) when Apply would refuse now (review A
  L4); a base without a final line break still reads verified once applied (review B L1). Answer: the thread, its hash, the entry, `scenario {name, file, hash, previous {text, hash}}` (Undo
  apply = the Studio's `restore` of `previous`: a version the engine read), the label, the validation warnings.
- Preview (`Engine.timeline.view({…, proposal: {comment_id, entry_id}})`, critique B9): on every call, before the memo,
  `proposalForPreview` checks the thread (of this scenario, open), the entry (actionable), rebuilds the text and runs the

  never a version `restore` accepts (`prepareScenarioEdit` remembers nothing; the view carries no `text`). The view says

**The proposal view** (L4.6 part D2, packages/ui `app/ProposalPanel.tsx`, pure rules in `app/comment-words.ts`;

  3 context lines; the engine's context after a change stops before the next one, so no line shows twice) as a table —

  "Show all"), and the buttons come after the whole diff (review A M1: the engine refuses a diff of more than 600 rows
  when Claude writes it); a fixed table layout, each row clipping its own ink. Each line is code-safe (`linePieces`): a
  `<code dir="ltr">` with `unicode-bidi: bidi-override` (byte order, left to right: right-to-left letters never reorder
  the digits and signs around them; such a row is marked "right-to-left text" — review A L6), monospace, `white-space:
  pre-wrap`, `overflow-wrap: anywhere`; leading and trailing spaces as `·`, tabs as `→`, every combining mark past the
  third on one character as `[U+…]` (review A L6), every character of core's

  `[U+…]`; a joiner between two pictographs and a variation selector after an emoji stay (emoji sequences, as core's
  write rules allow). Markup and right-to-left text are text nodes. So an indentation-only or a trailing-space change is
